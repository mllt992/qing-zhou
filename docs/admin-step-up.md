# 高风险操作的密码二次验证

管理员登录会话不是高风险操作的全部凭据。执行下列操作时，面板会弹出统一的「确认当前密码」窗口；同一登录会话、同一操作范围内的验证最多复用 **5 分钟**。普通只读页面、列表、统计和更新状态查询不增加密码弹窗。

## 保护范围

| 操作范围 | 受保护的操作 |
| --- | --- |
| `admin:backup` | 下载整库备份、升级快照、远端备份下载地址，手动创建/删除远端备份 |
| `admin:cert-export` | 证书私钥导出，TLS/Reality 完整编辑/克隆数据，含密钥的 sing-box 配置预览及远端导入预览 |
| `admin:update` | 在线更新、指定版本安装、二进制回滚、节点 sing-box/探针重装 |
| `admin:ssh` | 创建/修改/删除服务器连接信息，清除已固定的 SSH host key |
| `admin:user-security` | 管理员编辑用户账户、重置用户节点凭据 |
| `admin:security-settings` | 系统设置、OAuth、API Token 创建/撤销、TLS 配置变更、远端备份配置/计划、上游账户凭据变更 |
| `user:subscription-reset` | 用户更换自己的订阅地址 |
| `user:node-credentials-reset` | 用户重置自己的节点凭据 |

TLS 列表不再回传已存储的证书私钥或 Reality 私钥。点击编辑/克隆后，前端通过受保护的完整详情接口加载原值，然后填充表单；取消验证不会打开或提交编辑表单。已保存的未知扩展字段不会因列表脱敏而被占位符覆盖。证书私钥导出已改为 **POST**，旧 GET 导出不再可用。

用户取消、关闭验证窗口或切换页面时，原操作不会自动重试。输入错误密码仍保留当前登录状态；需要时可以重新输入。验证请求按用户及可信来源 IP 同时限流（默认每用户 10 次/10 分钟，每 IP 30 次/10 分钟，包括成功尝试），429 响应包含 `Retry-After`。有反向代理时应正确设置 `QZ_TRUSTED_PROXIES`，不能信任任意客户端传入的转发头。

## API 调用

1. 先以正常 JWT / Cookie 登录会话调用目标接口。缺少有效 proof 时返回 HTTP 403，响应中的 `data.error` 为 `step_up_required`，`data.scope` 为该操作要求的范围。中间件在执行业务操作之前拒绝请求。
2. 调用 `POST /api/user/reauth`，JSON 传入当前密码 `password`、上一步的 `scope`，以及可选 `method: "password"`。响应包含 `proof`、`scope`、`expires_in: 300`。普通用户不能取得管理员范围的 proof；目前只支持密码方式，未来可扩展其他验证方法。
3. 在目标请求的 **`X-QZ-Step-Up` 请求头**中携带 proof，保留原登录认证。前端只在收到上述明确 challenge 后重试一次；网络错误、业务错误和第二次拒绝不会自动重复提交。

proof 与用户 ID、当前登录会话 jti、操作范围和当前密码版本绑定，不是登录令牌。改密码（包括保留当前会话的自己改密码）、密码重置、注销及撤销会话都会使既有 proof 失效；账户封禁或管理员权限取消也会拒绝操作。proof 不写数据库、浏览器持久存储或 Cookie；所有验证/敏感导出响应都标记 `Cache-Control: no-store`。

必须通过 HTTPS 使用面板。不要把密码或 proof 放在 URL、截图、工单或日志里；反向代理/APM 也不要记录 `X-QZ-Step-Up`、Authorization 或 reauth 请求体。后端不记录验证密码、proof 或私钥。

### 机器备份兼容性

现有 `backup:write` API Token 仍只允许 `GET /api/admin/backup` 自动下载整库备份，继续执行原有 token scope、过期、撤销及账户状态检查。这是对已存在机器备份接口的明确兼容例外；Token 不能获取 password proof，也不能调用证书/TLS 私钥导出、升级快照下载、更新/回滚、SSH 或安全设置变更。浏览器管理员会话不能利用此例外。不要把具备整库下载权限的 Token 交给不可信集成。

## 忘记密码或无法验证

- 如果已绑定可用邮箱且配置了 SMTP，使用登录页「找回密码」完成密码重置，再重新登录。只使用 OAuth 登录、从未设置可用本地密码的账户也应先通过已验证邮箱恢复本地密码。
- 不具备邮件恢复条件时，由拥有主机权限的管理员停服、备份数据库后离线恢复账户。使用可信的本地工具生成新的 bcrypt 密码哈希，仅替换对应 `users.password_hash`，并删除该用户的 `sessions` 行，再启动服务并重新登录。不要把明文密码写入数据库、命令历史、工单或日志；不要修改 `QZ_SECRET_KEY`，否则原有加密配置可能无法解密。
- `QZ_ADMIN_PASS` 仅用于首次初始化，不会覆盖已存在账号的密码。没有可以在后台关闭二次验证或绕过限流的开关；不要为恢复账户而移除验证中间件。
- 如果问题来自升级导致服务无法启动，使用[灾备恢复指引](disaster-recovery.md)恢复匹配的数据库和二进制。回滚二进制不等于数据库降级。
