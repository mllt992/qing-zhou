# 轻舟面板 · 部署与配置手册

> 管理员向。从零把「轻舟 + sing-box」跑起来，并接入节点、套餐、订阅。

## 总体架构

轻舟是**单文件 Go 程序**（内置 Vue 前端 + SQLite），负责：用户/套餐/订阅/统计/可视化管理。
真正承载流量的是 **sing-box**（独立 systemd 进程）。轻舟生成 sing-box 配置并下发，
通过 sing-box 的 `v2ray_api` 采集每用户流量。一台机器可同时跑面板和 sing-box；
也可面板在中心机、落地 sing-box 在多台机器（面板用 SSH 下发）。

---

## 一、安装 sing-box（一键）

在**每台要做落地的服务器**上执行：

```bash
# 脚本由面板托管，把域名换成你自己的面板地址
curl -fsSL https://<你的面板域名>/install-singbox.sh | bash
```

> 面板「**系统设置 → 面板访问地址**」里会依据你配置的地址生成**可一键复制**的完整命令，
> 无需手工拼域名。地址来源优先级：环境变量 `QZ_PUBLIC_BASE` > 设置页「访问地址」> 反代头/请求 Host。

脚本会：

1. **已装则自动检测**，打印版本与路径，不重装（要重装加 `--force`）；
2. 未装则安装**本项目发布页的 sing-box** 到 `/usr/local/bin/sing-box` —— 与上游同版本、同功能，
   但额外编入了 `with_v2ray_api`；装完当场 `sing-box version | grep with_v2ray_api` 验一次；
3. 建 `/etc/sing-box/config.json` 占位配置 + `sing-box` systemd 服务并启动；
4. 应用**网络内核调优**（BBR + fq + 收发缓冲区 + somaxconn + tcp_notsent_lowat + 文件句柄上限，要跳过加 `--no-tune`）；
5. 最后打印一段「服务器」信息，照着填进面板即可。

输出示例：

```
════════ 安装完成，请到面板「服务器」处填写 ════════
  服务器地址(host)   : 1.2.3.4
  SSH 端口           : 22
  SSH 用户           : root
  sing-box 二进制     : /usr/local/bin/sing-box
  配置路径(config)   : /etc/sing-box/config.json
  systemd 服务名      : sing-box
  v2ray_api 监听      : 127.0.0.1:18080
```

> 占位配置是空的，sing-box 会先空跑；面板接管后会用真实配置覆盖并重启。

> ⚠️ **千万别自己去装官方版 sing-box。** 官方 release **不含** `with_v2ray_api`（上游文档：
> *V2Ray API is not included by default*），而面板正是靠它读取每用户流量。装了官方版的节点：
> **流量恒为 0、配额永不生效，而界面上完全看不出异常** —— 你会以为一切正常，直到发现没人被限速。
> 脚本从发布页下载失败时会回退官方版，但会明确告警；「服务器管理」页也会把这种机器点出来，
> 可**逐台一键重装**成正确的构建。

## 二、部署轻舟面板

### 2.0 一键脚本（推荐，跳过下面的手动步骤）

在面板机上以 root 执行，自动识别架构、下载最新 release、校验 SHA-256、引导配置、装好 systemd 并启动：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mllt992/qing-zhou/main/install.sh)
```

脚本会问**「面板打算怎么访问」**，这一项最容易踩：

| 选项 | 写入的 `QZ_LISTEN` | 什么时候选 |
|---|---|---|
| **1（默认）** | `0.0.0.0:8081` | 直接用 `http://服务器IP:8081` 打开 |
| **2** | `127.0.0.1:8081` | 前面有 nginx / Caddy 反代（本手册第 4 步） |

> 选了 2 却没配反代，表现是**「装成功了却打不开」**。不必重装：
> ```bash
> sed -i 's|^QZ_LISTEN=.*|QZ_LISTEN=0.0.0.0:8081|' /opt/qingzhou/qingzhou.env && systemctl restart qingzhou
> ```
> 云服务器另需在**安全组 / 防火墙**放行该端口。

常用参数：`--version vX.Y.Z` · `--force` · `--proxy https://mirror.ghproxy.com/`。
**重跑同一条命令 = 原地升级**（配置与数据库不动、二进制原子替换，并刷新 `QZ_PROBE_DIR` 里的探针）。

**卸载**（安装时脚本已把自身存了一份到 `/opt/qingzhou/install.sh`）：

```bash
bash /opt/qingzhou/install.sh uninstall
```

先停服务、删 systemd 单元与二进制，再单独确认是否删除 `/opt/qingzhou`（数据库 / 配置 / 探针）——输 `yes` 才删，默认保留。落地机上的 sing-box 与探针是独立安装的，**不在面板卸载范围内**，要清干净得上落地机 `systemctl disable --now sing-box qingzhou-probe` 再删对应文件。

### 2.1 手动部署

1. 把 `qingzhou` 二进制放到 `/opt/qingzhou/qingzhou`（`chmod +x`）。
2. 写 `/opt/qingzhou/qingzhou.env`（`chmod 600`），常用变量：

   ```ini
   QZ_LISTEN=127.0.0.1:8081                # 有反代才用回环；要 IP:端口 直连须改 0.0.0.0:8081
   QZ_DB=/opt/qingzhou/qingzhou.db
   QZ_PUBLIC_BASE=https://你的面板域名      # 可选：面板访问地址，也可在「系统设置」里填；设了环境变量则以其为准
   # 反代不在本机时必须设，否则面板不信任转发头（防伪造源 IP），限流与邮件/订阅链接
   # 拿到的都是反代的 IP。同机回环反代无需设置。
   # QZ_TRUSTED_PROXIES=10.0.0.5,172.18.0.0/16
   QZ_SECRET_KEY=<openssl rand -hex 32>    # 加密库内敏感配置的主密钥，务必设置
   QZ_SSH_KEY_DIR=/opt/qingzhou/ssh-keys   # 可选，SSH 私钥文件目录（默认 = 数据库同级的 ssh-keys/）
   QZ_SINGBOX_CONFIG=/etc/sing-box/config.json
   QZ_SINGBOX_UNIT=sing-box
   QZ_SINGBOX_BIN=/usr/local/bin/sing-box
   QZ_SINGBOX_V2RAY=127.0.0.1:18080
   # 探针监控（可选）：探针二进制所在目录，面板据此提供下载。默认相对路径 cmd/probe/dist，
   # 二进制部署时几乎必设为绝对目录，见下「探针监控」。
   QZ_PROBE_DIR=/opt/qingzhou/probe
   # 初始管理员（仅首次启动生效）：不设 QZ_ADMIN_PASS 则随机生成并打印到日志
   # QZ_ADMIN_USER=admin
   # QZ_ADMIN_PASS=
   # 可选 SMTP（邮箱验证/找回）：QZ_SMTP_HOST / QZ_SMTP_USER / QZ_SMTP_PASS ...
   ```

   > 说明：JWT 密钥由程序**首次启动自动生成并存入数据库**，无需手动配置；`QZ_SECRET_KEY`
   > 是用于加密库内敏感配置（SMTP 密码 / Reality 私钥等）的主密钥，建议置于环境变量、不入库。

3. 装 systemd 服务（仓库 `deploy/qingzhou.service`）：

   ```bash
   cp deploy/qingzhou.service /etc/systemd/system/
   systemctl daemon-reload && systemctl enable --now qingzhou
   ```

4. 前置 Nginx/Caddy 反代到 `QZ_LISTEN`，配 HTTPS（订阅与面板都走 https）。反代**不在本机**时记得设 `QZ_TRUSTED_PROXIES`。
5. 备份：仓库 `deploy/backup.sh` 挂 cron（每日热备 SQLite，留 7 天）。面板「在线更新」页也能**一键导出整库一致性快照**（`VACUUM INTO`，单文件、无 `-wal` 附件），临时备份用它更省事。

首次访问会建管理员账号（或用初始账号登录后改密码）。

### 高风险操作的密码二次验证

导出数据库/升级快照/证书私钥、修改 SSH 连接或 host key、安全设置、更新/回滚及用户凭据重置等操作，现需确认当前密码。同一会话及操作范围的验证最多复用 5 分钟，改密、注销或撤销会话后失效；普通列表、监控与统计读取不变。TLS 列表不会回传私钥，显式编辑/克隆时才验证并加载完整详情。

请部署 HTTPS，并避免在反向代理/APM 中记录 reauth 请求体、Authorization 或 `X-QZ-Step-Up` 请求头。忘记密码时优先使用已配置 SMTP 的邮件找回；无邮件恢复条件时由主机管理员离线恢复账户，`QZ_ADMIN_PASS` 不会重置已存在账号。具体 API 契约、限流、机器备份兼容性和恢复步骤见[二次验证说明](admin-step-up.md)。

## 三、面板内配置顺序

> 入口在后台左侧菜单。建议按此顺序一次配好。

### 1. 服务器（多落地才需要）
本机落地直接用默认值即可。远程落地：**服务器 → 新增**，填安装脚本输出的 host/SSH/路径。
面板会 SSH 校验并下发配置。

添加完成后，本页会长期显示每台机器**实际在跑的 sing-box 版本**（数据来自面板本来就在做的能力探测，不额外连机器）：

- **版本标红** = 低于面板要求的最低版本。这种情况下该机的 `sing-box check` 会失败、面板**停止向它下发任何配置**，而界面别处看不出异常 —— 看到红的就处理。
- 缺 `v2ray_api`（流量统计不到）同样会在这里点破。
- 两种情况都可**逐台一键重装**成面板发布的版本：安装脚本经 SSH 推过去执行，**节点无需能访问面板**。

#### 用普通用户登录（sudo 提权）

AWS / GCP / Oracle Cloud 以及多数 Ubuntu 云镜像默认关掉 root SSH，只给一个普通账号。
这种机器把「SSH 用户」填成该账号，并打开 **sudo 提权** 开关即可 —— 写配置、装配置、
重启服务、重装 sing-box 都会走 sudo。

- 优先给它配**免密 sudo**：`visudo` 里加 `<用户> ALL=(ALL) NOPASSWD:ALL`；
  否则在「sudo 密码」里填密码（密码走 SSH 会话的标准输入，不会出现在节点的 `ps` 里）。
- sudoers 里如果有 `requiretty`，非交互 sudo 会被挡住，需要去掉。
- 配好后点**测试连接**：面板会先验证一次提权，不通会直接告诉你差什么。

> ⚠️ **这不等于降权。** 面板需要执行的是「往 /etc 写文件、重启 systemd 单元、跑安装脚本」，
> 免密 sudo 到这个程度和直接给 root 没有实质区别。用普通用户的收益是符合云厂商默认配置、
> 以及审计里能看到是谁在提权，**不是**把面板的权限限制住了。

#### 私钥放文件，不粘贴到面板

私钥可以只放在面板机器上，服务器行里只存一个**文件名**：

- 目录默认取数据库所在目录下的 `ssh-keys/`（Docker 是 `/data/ssh-keys`，一键脚本装的是
  `<安装目录>/ssh-keys`），用 `QZ_SSH_KEY_DIR` 可以改。
- 把私钥放进去并 `chmod 600`，然后在「SSH 私钥」处切到**从文件选择**。
- 私钥内容不会经过浏览器、也不会入库。
- **Docker 注意**：容器内面板以 `uid 10001` 运行，宿主机上 root 拥有的 600 私钥挂进去
  **读不了**。需要 `chown 10001 <私钥>`。下拉框里会直接标出「面板读不了」，不用猜。

### 2. TLS / Reality
**sing-box → TLS**：
- **Reality**（推荐）：一键生成 x25519 密钥对 + short_id，填一个**借用域名**（`handshake server`，
  如 `www.microsoft.com`）。抗封锁、无需自有证书。
- **证书 TLS**：有自己的域名证书时用；可直接引用「证书管理」里的证书（见 2.1），也可就地粘贴或一键自签。

#### 2.1 证书管理（真实证书 / 自动续期）
需要真实证书的场景（套 CDN 的 WS-TLS、想让浏览器/系统信任的 mixed HTTPS 代理等），到 **证书管理** 统一签发和托管，证书**全局复用**、可被任意入站的 TLS 引用：

- **ACME 在线签发**（Let's Encrypt）：默认走 **Cloudflare DNS-01**——先在「**系统设置**」填一个 Cloudflare API Token（权限：`Zone → DNS → Edit`，作用域含该域名的 Zone），再在证书管理里填名称 + 域名一键申请；也支持 `http-01` / `webroot`。签发在**面板所在机**完成，不需要落地机开 80 端口。
- **兼容策略**：新证书默认「自动兼容」，当前采用 RSA 2048 并优先选择 `ISRG Root X1` 链；「最大兼容」固定这组参数，「现代优先」使用 ECDSA P-256 与 CA 默认链。自动策略与具体参数分离，后续版本可随客户端生态演进；已有证书的策略保持为空并沿用旧行为，升级本身不会换密钥或换链。
- **签发核验**：面板会在保存和下发前检查证书/私钥匹配、申请域名（SAN）、有效期及系统信任链，并记录实际密钥类型与验证链。续签结果若核验失败，数据库和节点继续使用上一张可用证书，只显示错误等待处理。
- **粘贴导入**：把已有的证书 PEM + 私钥粘进来（域名默认取证书 CN）。
- **一键自签**：给定 SNI 生成自签证书，适用于 TUIC / Hysteria2 等允许 `insecure` 或用证书指纹的客户端。
- **自动续期**：ACME 证书默认开启自动续期，后台定时器在临近到期时续签并**推送到引用它的各落地机**；也可在证书列表手动「立即续期」。粘贴/自签证书不自动续，到期需重新导入。
- 仍被 TLS 配置引用的证书不允许删除。

> 证书密文用 `QZ_SECRET_KEY` 加密落库；换过该密钥会导致旧证书解不开，列表会标记「无法解密」，此时拒绝写回以免覆盖成空。

### 3. 入站（节点）
**sing-box → 入站**：选协议建入站，绑定上一步的 TLS。推荐组合见下「协议选型」。
同一台机可建多协议入站（vless/hysteria2/tuic…），用户订阅会自动聚成「固定IP·只切协议」优选组。

#### 3.1 中转 / 落地链路（可选）
让 A 机做**线路机**、B 机做**落地机**：`客户端 → A 入站 → B 入站 → 互联网`。适合国内到线路机链路好、线路机到落地机再出海的场景。

- 在 A 的入站里把「**落地 / 中转**」设为 B 上某个入站；或在 **sing-box → 链路拓扑** 里给 A 入站点「**＋ 串联落地**」直接新建 B 落地并自动关联。
- 面板会在 A 生成一个拨号 B 的出站 + 路由，并在 B 的入站里注入一份**自动派生的中转凭据**（无需你手工配隧道）；两端凭据同源。
- **支持多级链式**：B 本身也可再设一个上游落地 C，链成 `A → B → C → 互联网`（拓扑图逐级展示、并自动防环）；末端还能接一个第三方代理出口（见下）。
- 约束：落地入站需为可作出站的协议（vless / vmess / trojan / shadowsocks / hysteria2 / tuic）；per-user 流量计量始终在**入口 A 侧**完成。
- 「链路拓扑」里可一键「**解除中转**」恢复直接出网。

**一个线路入口复用多个落地**：到 **节点管理 → 节点** 编辑自建节点，在「**固定落地**」选择该节点要走的落地入站；也可以点节点卡片的「**复用入口**」快速创建另一条线路。多条节点可以绑定同一个入口 Tag，因此线路机只监听一个 IP / 端口并复用同一套 TLS、协议和传输配置；面板会为每条逻辑线路派生独立的用户凭据，并按认证用户路由到对应落地。用户订阅里仍显示为多个可单独选择的节点，流量统一计入原套餐。

- 未选择「固定落地」的旧节点继续继承入口入站原有的「落地 / 中转」设置，升级不会改变既有链接或凭据。
- 固定落地与该落地后续的多级中转兼容，例如共享入口可分别形成 `A → B → 互联网`、`A → C → D → 互联网`。
- 固定落地被删除或停用时，该逻辑节点 **fail-closed**：停止下发派生身份并暂时从订阅隐藏，绝不会静默改成从线路机直出；节点管理拓扑会保留告警，直到重新选择落地或明确改回继承链路。
- Mixed（HTTP/SOCKS5）入口暂不支持这种按逻辑线路分流；普通代理账号仍保持跨节点复用，避免已有工具中的用户名发生变化。

#### 3.2 第三方代理出口（可选，静态 IP）
让某入站不直接出网，而是经一个**购买来的 SOCKS5 / HTTP 代理**（例如固定住宅/机房静态 IP）出网 —— 出口 IP 即该代理的 IP。

- 在 **sing-box → 代理出口** 录入代理（类型 socks/http、地址、端口、账号密码，密码库内加密存储）；再在入站的「**代理出口**」里选它。「代理出口」与「落地 / 中转」**二选一**。
- **类型必须和供应商给的协议一致**：选错的表现是连上后立刻被 RST（对端读不懂握手包），不是超时。高位随机端口通常是 SOCKS5。
- **HTTP 代理只转发 TCP**：TUIC / Hysteria / QUIC 等依赖 UDP 的入站请改用 **SOCKS5** 出口，否则 UDP 静默失败。
- 代理若因换了 `QZ_SECRET_KEY` 解不出密码，出站以空密码下发让流量在代理侧「**fail-closed**」，不会悄悄回落成直连（避免暴露真实 IP）。
- 仍被入站引用的代理出口**不允许删除**。

**TLS 到代理这一跳（HTTPS 代理，可选）**：开启后到代理的 CONNECT 与账号密码走在 TLS 里，不再明文过网。仅 **HTTP 类型**可用 —— sing-box 的 SOCKS5 出站没有 TLS 选项，面板会直接拒绝这个组合，而不是存下一个「看着加密、实际明文」的配置。

- **端口是 443 不等于要开**：很多代理只是借 443 穿墙，实际是明文 HTTP/SOCKS5；开错的报错形如 `proxyconnect ... tls: failed to verify certificate`。
- **SNI**：地址填 IP 时几乎一定要填，否则报 `cannot validate certificate for <IP> ... doesn't contain any IP SANs`（证书签给的是域名，不是 IP）。
- **信任证书**：这一跳面板是 **TLS 客户端**，这里选的证书只用来**校验对方**，不会发出去，私钥那一半也用不上（sing-box 出站不支持 mTLS 客户端证书）。商用代理保持「系统根证书」；只有代理是**你自己搭的**、用的正是「证书管理」里那张证书（含自签）时才需要指定，指定后 SNI 留空会自动取证书域名。
- 引用的证书若丢失或解不出，出站仍保留 `tls.enabled`，握手失败即止 —— 不会退回明文把凭据交出去。
- **跳过证书校验**仅供临时排障：凭据就在这条 TLS 里，跳过校验等于允许中间人拿走并盗用你的出口。

### 4. 分组
**分组**：把节点归类（如「免费」「高级」「自建」）。订阅/套餐都按分组授权。
- **免费分组**：在「设置」里指定 `free_group_id`，所有用户可见；不想送就设「不设」。

### 5. 套餐
**商品**：建套餐（流量包 / 套餐型），绑定可访问的分组。
- 重复购买同套餐会**排队生效**（不再叠加：新买的份排队，当前份用完/到期后自动顶上），不同套餐各自独立计费（桶模型）。
- 退款默认**按剩余流量/时间比例**结算（可在「系统设置 → 退款策略」调整方式/基准/手续费）。
- 下架被订阅的商品要走「**下架**」流程（二次确认→按比例退积分→清空订阅者套餐），不要硬删。
- 完整的购买 / 续费 / 多套餐 / 退款规则见 **[计费与退款业务说明](计费与退款业务说明.md)**。

### 6. 机场订阅源（可选）
**节点源**：粘贴机场订阅链接，可绑定分组、定时抓取（支持 base64 / Clash YAML）。

### 7. 探针监控（可选）
在每台服务器装轻量探针 `qingzhou-probe` 上报 CPU/内存/磁盘/负载，面板「监控管理」展示并告警。

- 安装命令在「**监控管理**」页获取，形如 `bash <(curl -sL <面板地址>/api/monitor/install.sh) <探针Token>`；
  脚本里的面板地址同样取自上面的「访问地址」（`QZ_PUBLIC_BASE` > 设置页 > Host）。
- **探针二进制由面板托管下载**（`/api/monitor/agent/linux-<arch>`），从磁盘目录 `QZ_PROBE_DIR` 读取
  （默认相对路径 `cmd/probe/dist`）。**二进制部署时该相对目录通常不存在，会导致探针安装报
  “下载失败: HTTP 404”**。解决：
  1. 从本项目 GitHub Release 下载 `probe-linux-amd64` / `probe-linux-arm64`；
  2. 放到一个目录（如 `/opt/qingzhou/probe/`），文件名保持不变；
  3. 在 env 里设 `QZ_PROBE_DIR=/opt/qingzhou/probe` 并重启面板。
- **`install.sh` 原地升级会刷新该目录里的探针；面板「在线更新」现在也会。** 只替换面板二进制、不刷新探针时，「一键升级」会把旧探针（没有 `-version`）装上去：服务能起来，但安装任务会报「读取版本失败」。从本版本起，新面板启动时会按自身版本把 `QZ_PROBE_DIR` 对齐到同一次 release（已一致则跳过下载）。因此用「在线更新」升到本版本后，不必再跑一遍 `install.sh` 才能装到带 `-version` 的探针。
- 告警阈值（CPU/内存/磁盘）在「系统设置 → 监控告警阈值」调整。

## 五、运维排错

- **面板装完打不开**：`QZ_LISTEN` 是回环地址而你没配反代。见 2.0 的修复命令；再查安全组与本机防火墙。
- **改完不生效**：面板每改动会重建配置；后台也有约 1 分钟的定时重建。
- **某落地下发失败**：到 **sing-box → 链路拓扑**，失败的机器下面直接写着这次的原因
  （SSH 连不上、节点上 `sing-box check` 不过等），右侧「重新下发」可重试；多为该机
  sing-box 版本对配置项要求不同（如 `domain_strategy` 在 1.12+ 改写）。先看「服务器」页
  该机版本是否标红，标红就直接一键重装；否则升级/降级该机 sing-box 或调整配置。
  注：这个状态只存在内存里，面板重启后会清空，等下一次重建或点「重新下发」才会重新出现；
  历史记录仍要看面板日志 `sbctl: server N apply error: ...`。
- **统计无数据（所有人都是 0）**：八成装了官方版 sing-box。落地机上跑
  `sing-box version | grep with_v2ray_api`，没输出就是装错了，到「服务器」页一键重装。
  插件在但仍无数据时，再查 `QZ_SINGBOX_V2RAY` 与配置里 `experimental.v2ray_api.listen`
  是否一致（默认 `127.0.0.1:18080`）。
- **sing-box 启动失败**：`journalctl -u sing-box -n 50`，或 `sing-box check -c /etc/sing-box/config.json`。
- **客户端导入 sing-box 订阅报错 / 加载失败**：客户端需 **≥ 1.12**。1.14 移除了旧的 DNS `address`
  写法（`dns.servers` 与 `route.default_domain_resolver` 两处），旧写法在 1.14 上是**直接加载失败
  而非告警**。面板下发时会把自定义模板自动改写成新写法，但客户端太老（< 1.12）读不懂新写法。
  Clash / Surge / base64 订阅不受影响。
- **升级后面板起不来**：「在线更新」页点**回滚**——用的是升级时留在本机的旧二进制，**不联网、
  不重新下载**，所以这条路在新版本崩了或网络不通时依然可用。也可指定安装任意历史版本。
- **节点访问不到内网服务是正常的**：生成的配置**默认阻断私网出口**（内网段 / `127.0.0.1` /
  云元数据 `169.254.169.254`），用域名指向内网也拦得住（先解析再判断）。这是防止用户借节点
  探测落地机内网，不是 bug。
